# À lire en premier — application automobile

## Où en est le projet ?

La conception est enregistrée. Une première version de développement a maintenant été construite et testée dans `../application`. Pour la lancer, lire `../application/GUIDE-DEBUTANT.md`. L’état réel des fonctions livrées et restantes est suivi dans `../application/ETAT-DU-PROJET.md` ; la cible complète n’est pas encore livrée.

Les choix utilisateur permettent de commencer le socle. Restent à résoudre pendant la préparation et la réalisation : essais de l’IA sur le PC, données de réparation et de fiabilité, calibration des scores, installation des outils, sécurité du réseau domestique et tests de réception. Les fonctions non validées ne doivent pas être présentées comme terminées.

## Documents à lire dans cet ordre

1. `cahier-des-charges.md` : les 38 décisions utilisateur.
2. `recommandations-et-faisabilite.md` : compléments retenus par délégation.
3. `validation-technique.md` : test de recherche réel, limites, architecture, calculs et tests attendus.

Ces fichiers Markdown (.md) sont de simples documents texte, pas des programmes. `consolider.py` est un ancien outil de rangement des documents : ne pas le lancer pour démarrer l’application.

## Démarrer le développement dans ce chat

Le chat actuel a déjà accès au dossier. Aucun transfert de fichier n’est nécessaire. Envoyer :

« Lance le développement de l’application automobile à partir de conception/LIRE-MOI.md. Lis les trois documents référencés et respecte les décisions prises. Commence par vérifier les prérequis puis construis et teste le socle dans un sous-dossier application. Poursuis par étapes vers toutes les fonctions prévues. Résous les choix techniques avec tes recommandations, sans relancer le questionnaire. Signale les vraies limites et les validations encore nécessaires. Préserve sources/ en lecture seule. Ne souscris aucun service payant. Prépare à terme un lancement Windows simple et un guide débutant. »

Cette demande lance le travail de développement, pas une application déjà terminée. Certaines installations peuvent nécessiter une autorisation distincte.

## Si le travail est repris dans un autre environnement local de développement

Copier l’ensemble du dossier conception dans le dossier de ce projet, puis donner la même instruction. Ne pas transmettre un seul fichier en oubliant les deux autres. Garder les études existantes sous livrables comme références si elles sont disponibles. Les instructions utilisateur priment sur les recommandations ; les propositions non mesurées restent identifiées comme telles.

## Livraison attendue

Code et ressources dans application/, documentation d’installation et d’utilisation, lancement Windows simple, tests exécutés et compte rendu distinguant fonctions livrées et limites. Ne pas annoncer une livraison complète à partir d’une maquette ou d’un test isolé de source d’annonces.
